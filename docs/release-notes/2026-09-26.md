## Changes by bucket

### `reindex_auto` changes

#### Embedding model rework

- **What changed**
  - Vectors live only in the `embeddings` table, one row per object and model, with one ANN index per registered model at that model's measured dimension (SQLite vec0 table `vec_emb_<hash>`; Postgres partial HNSW index `idx_emb_<hash>`).
  - Queries read the default model on every query, so `set-default` applies to the next query in every process without a restart.
  - Ingest embeds each new object with every registered model that isn't deprecated.
  - Migrations, applied automatically on the first open by `dpkms serve` or any `ctxt` command:
    - SQLite 037: rebuilds `embeddings`, drops the `legacy-blob` placeholder model with its rows and signature, and builds each registered model's index.
    - SQLite 038: drops `vec_objects`, `object_embeddings` and the `objects.embeddings` and `objects.vector_indexed` columns.
    - Postgres 14 and 15: the same, dropping `objects.embedding` (with its HNSW index) and `objects.vector_indexed`.
- **Signature bump**: the `embeddings_legacy-blob-<dim>@2026-05-07` signature is deleted. Each registered model gets an `embeddings_<model_id>` signature over its index DDL. A mismatch rebuilds that model's index from its rows on the next open.
- **Estimated wall-clock**: SQLite 038's `DROP COLUMN` rewrites the whole `objects` table, holding the write lock. Measured: about 6 s for 100,000 objects (420 MB database) on a laptop SSD; expect it to scale with database size. Keep free disk space for the rewrite. Postgres drops columns without rewriting the table (not measured).
- **Why `reindex_auto`**, per ADR-070 §1:
  - Stored knowledge is untouched: no object is re-ingested, no `pipeline_version` changes, and the daemon never refuses to serve.
  - The upgrade itself is schema and index work detected and run on open, which is the `reindex_auto` shape. The per-model index is stamped and rebuilt through `index_signatures` (ADR-071, amendment §3).
  - It isn't `reingest_selective` or `reingest_all`. Filling vectors is not a re-ingest: `ctxt embeddings migrate` runs only the embedding step. It is operator-initiated, rate-limited, restartable, and search keeps serving throughout. ADR-071 exists to take a model change out of `reingest_all`.
  - Nothing that worked before stops working on a typical instance. Ingest never produced vectors (the embedding step had no provider), so local instances had 0 coverage and search was already full-text in practice. It now says so with a notice instead of silently.
  - One exception: an instance where `dpkms dev reindex-vectors` was run had real vectors in `object_embeddings`. Migration 038 drops them. Search on that instance falls back to full-text, with the notice, until a model is registered, migrated and made the default.
- **Action required**: none for the upgrade itself. To turn semantic search on:

  ```bash
  ctxt embeddings register ollama-nomic-embed-text@2026-09-26
  ctxt embeddings migrate --to ollama-nomic-embed-text@2026-09-26
  ctxt embeddings set-default ollama-nomic-embed-text@2026-09-26
  ```

  Guides: [Turn on semantic search](../manual/workflows/semantic-search.md), [Operate embedding models](../manual/operations/embeddings.md).

- **Before upgrading a large SQLite database**, stop dpkms and back it up, for example `sqlite3 <db> ".backup '<db>.pre-038'"`.

#### Repeated text in the index projection

- **What changed**: the full-text body and the embedding text list each segment once. A root summary with the same text as a section, a section repeated in the document, or a body that repeats its summary used to be indexed twice (`X\nX`). Segments are compared with surrounding whitespace trimmed; the first occurrence keeps its place.
- **Signature bump**: the `objects_fts` signature's projection input goes from `v1` to `v2`. On its next start, `dpkms serve` prints `warning: FTS signature mismatch … reindex_auto pending`, publishes `dpkms.upgrade.signature.mismatched`, and stores the new signature, so the warning appears once.
- **Estimated wall-clock**: none at startup. The check compares two hashes.
- **What is not rebuilt**: the signature check reports the change but does not rebuild anything. Stored full-text bodies and existing vectors keep the doubled text until their object is written again, for example by re-analysis. `dpkms housekeeping reindex` rebuilds the SQLite FTS table from the stored bodies, so it doesn't pick up the change either. Search still finds the same objects; only the ranking of objects with repeated text differs.

### `none` changes (embedding rework, outside the data layer)

- **BREAKING, objects API JSON**: `embeddings` and `vector_indexed` are no longer part of an object. Coverage is per model: `ctxt embeddings list`.
- **Removed commands**: `dpkms dev reindex-vectors` and its deprecated alias `ctxt dev reindex-vectors`. `ctxt embeddings migrate --to <model_id>` queues a background job in dpkms. Follow it with `ctxt upgrade status` (bucket `embeddings_migrate`, with `target` and `failed`). There is no `--budget-usd` and no pause: stop a run with `dpkms job cancel <job-id>`, continue it by running `migrate` again. A run with failed objects leaves the status `failed` until the next run.
- **Removed `register` flags**: `--model-config`, `--provider`, `--make-default`, and the `$EDITOR` skeleton. Register measures the dimension from the provider.
- **New commands**:
  - `ctxt embeddings provider [model_id]` shows each resolved setting and its source.
  - `set-default` refuses a model below `embeddings.min_coverage`.
  - `deprecate --on <date>` stops dual-writing from a date.
  - `purge` deletes a deprecated model after `embeddings.grace_period`.
- **Config keys**:
  - `providers.embedding.{backend,model,endpoint,api_key_env,dimension}`; `providers.embedding.language` removed; backends are `ollama` and `stub`.
  - New `embeddings.min_coverage` and `embeddings.grace_period`.
  - `pipelines.overrides.<name>.providers.embedding` is ignored with a warning.
  - `duplicates.similarity_threshold` is a cosine similarity (1 − distance) on the default model's index.
- **A registered model's backend and model are fixed.** Flags, env and `-c` may change only its endpoint and `api_key_env`. An override that would change the backend or model fails the command, and `find` answers from full-text with a `provider_error` notice.
- **Duplicates**: with `duplicates.check_similar: true`, the `dedup` step now runs right after the embedding step in every embedding pipeline. Before, it was built without a store and never matched.

#### Known issues

- `ctxt embeddings register --dry-run` registers the model; preview with `ctxt embeddings provider` instead.
- `duplicates.policy: drop` marks a near-duplicate `suppress_output` but still stores it.
- A change to the FTS projection is detected but not applied to stored objects: no worker re-projects `projected_fts_body` or re-embeds when the signature doesn't match. Objects written before this release keep their doubled index text until they are written again.

### `none` changes (no operator impact at the data layer)

#### Browser capture

- **`ctxt capture tabs`** sends the tabs open in one Chromium-family browser profile (Chrome, Brave, Edge, Arc, Chromium, Vivaldi). Reads the profile's session file; no extension needed. `--dry-run` lists every tab with its allow/deny reason.
- **`ctxt capture history`** sends browsing history. No time flag: incremental from a saved position (first run looks back `capture.history.initial_lookback`, default `24h`). `--since` alone captures from that time and advances the position. `--until` / `--range` backfill without touching it. `--reset-position` clears one profile's position.
- **`ctxt capture browsers`** lists installed browsers and profiles and shows what auto-selection would pick.
- **`ctxt capture schedule install|uninstall|list`** manages macOS LaunchAgents that run the two capture commands on a timer, pinned to one browser profile.
- `--browser` is optional everywhere: flag → `capture.browser` → the only browser with that profile name → OS default browser.
- `capture.url_filter` deny rules add up across every config layer (user file, project file, `-c` files and values); no layer can remove one.

#### Config

- Config loading never writes files. The v0→v1 migration and its write-back into the highest-precedence file are removed, along with the `version` key.
