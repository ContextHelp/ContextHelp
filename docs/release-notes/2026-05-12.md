## Changes by bucket

### `none` changes (no operator impact at the data layer)

#### `feat(cmd/ctxt): enable kit 12fcc strict validation gates at boot` — T-0595

- **What changed**:
  - The live `kitcli.Config` literal in `cmd/ctxt/cmd/root.go` now sets `EnforceGuidance: true`, `EnforceDryRunRationale: true`, `EnforceDestructiveToken: true`, `SignatureStrictness: SignatureStrictnessReject`, and `PassthroughStrictness: "reject"`. Combined with the existing `EnforceValidate: true` (kit default) and `MaxTopLevelVerbs: 30`, this is the full strict-gate posture documented in ADR-068 / kit 12fcc-leak.
  - Boot-time `root.Validate()` is wired in `Execute()` because ctxt calls `fang.Execute(…, WithoutVersion())` directly (rather than kit's `root.Execute(ctx)`) so kit's implicit Validate pre-flight does not run. `ValidationFailureMode: ValidationFailureError` propagates failures as returned errors instead of `os.Exit(2)` from inside kit.
  - A new hermetic regression test `TestRootValidate_StrictGatesPass` (no build tag) in `cmd/ctxt/cmd/strict_validation_test.go` mirrors `Execute()`'s pre-flight and asserts `root.Validate() == nil`. Adding a new subcommand without the required annotations fails this test in every CI run before it can ship.
  - The build-tagged baseline probe driver (`cmd/ctxt/cmd/baseline_probe_test.go`, tag `ctxtbaselineprobe`) was retained for sprint-style bucket dumps. It is invisible to the default test command.
- **Why now**: T-0591/T-0592/T-0593/T-0594 closed every bucket the probe surfaced (160 commands, 5 distinct annotation classes, 1 cap raise, 11 hierarchical leaves, 31 local-global collisions). With the surface clean, the gates flip on so future regressions fail fast at boot.
- **Behavior delta for end users**: none at runtime. `ctxt --help`, `ctxt status`, `ctxt version` exit `0` with no stderr output, identical to pre-T-0595. The new behavior only fires when a future commit introduces a leaf without the mandatory annotations — at which point `ctxt` will print a `kitcli.ValidationError` and exit non-zero at boot.

#### `feat(cmd/ctxt): destructive confirmation via kit --confirm` — T-0594

- **What changed**:
  - The per-command `-y/--yes` flag is gone from every destructive ctxt leaf. Bypass moved to kit's global `--confirm` policy, which accepts `yes` (skip the prompt) and `prompt` (require `--confirm-token=<sha>`).
  - Affected leaves: `delete`, `profile delete`, `profile schema remove-*`, `config restore`, `cursor delete`, `detector remove`, `embeddings deprecate`, `embeddings purge`, `feed delete`, `inbox clear`, `inbox discard`, `link delete`, `registry delete`.
  - Each leaf is annotated `kit/side-effect=destructive` + `kit/destructive-token=required`. The kit validator now refuses to register a destructive leaf without the typed-token opt-in.
- **Behavior delta for users / scripts**:
  - Interactive use: the secondary friction prompt still appears unless `--confirm=yes` is supplied; behaviour matches the old `-y` skip path.
  - Non-interactive scripts: replace any piped-`-y` invocation with `--confirm=yes`. Token-gated automation: pair `--confirm=prompt` with `--confirm-token=<sha>` (kit derives the token from the command path + destructive arguments; the kit CLI prints the expected token on dry-run).

## Upgrade walkthrough

No data-layer migration. `make install` (or equivalent) and the new bin drops in.

Operator change-of-habit: any script that previously piped `-y` to `ctxt delete` (or any other listed destructive leaf) must move to `--confirm=yes`. Example diff:

```diff
- ctxt delete --id obj_abc123 -y
+ ctxt delete --id obj_abc123 --confirm=yes
```
