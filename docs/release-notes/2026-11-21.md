## Changes by bucket

### `reingest_selective` changes

- **What changed** — the `html_cleaner` step, used by `url.generic`, `url.authenticated`, `url.interactive`, `url.repo` and every `url.github.*` pipeline. It parses HTML instead of stripping tags with regular expressions. Page chrome (`head`, `nav`, `header`, `footer`, `aside`, `form`, `noscript`, `template`, `iframe`, `svg`, and elements with landmark roles `banner`, `navigation`, `contentinfo`, `complementary`) is dropped; text comes from `<main>`, else the outermost `<article>` elements, else the body. The page title moves from the body text to the `title` metadata key.
- **Selector predicate** — `pipeline LIKE 'url.%'`.
- **Versioned pipeline?** — no. Built-in pipelines carry no version yet; existing objects are selected by pipeline name.
- **Estimated wall-clock** — one re-fetch and pipeline run per stored web page; depends on corpus size and the sites' response times.
- **Estimated LLM cost** — the `url.*` pipelines run tagging, entity extraction and embedding steps, so cost scales with the number of re-ingested pages and the configured providers.

## Upgrade walkthrough

1. **Before upgrading** — back up: `dpkms backup` (add `--include-blobs` to keep local blobs).
2. **Pull / install** — install the release as usual.
3. **Preview** — `ctxt upgrade run --filter "where:pipeline LIKE 'url.%'" --dry-run` lists the pages to re-ingest.
4. **Run** — `ctxt upgrade run --filter "where:pipeline LIKE 'url.%'"`. Re-ingesting fetches each page again: content that changed or disappeared upstream changes or fails.
5. **Verify** — `ctxt upgrade status --watch` until done.
6. **Roll back if needed** — `dpkms restore <archive>`.
