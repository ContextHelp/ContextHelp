## Changes by bucket

### `reingest_selective` changes

- **What changed** — the `html_cleaner` step. It parses HTML instead of stripping tags with regular expressions. Page chrome is dropped: `head`, `script`, `style`, `noscript`, `template`, `nav`, `iframe`, `svg`, form controls (`input`, `select`, `textarea`, `button`, `option`), elements with `hidden` or `aria-hidden="true"`, page-level `header`, `footer` and `aside` (those inside an `article`, `main` or `section` stay), and elements with the landmark roles `banner`, `navigation`, `contentinfo`, `complementary`. Text comes from `<main>` (or `role="main"`), else the outermost `<article>` elements, else the body. If that leaves nothing, the step retries keeping everything except `head`, `script`, `style`, `template` and `noscript`. Page chrome is removed by structure only: a cookie notice in the body outside every landmark stays. The page title moves from the body text to the `title` metadata key. Documents nested more than 512 elements deep use a simpler text pass (no `<main>` or `<article>` preference, no roles).
- **Pipelines affected** — `html_cleaner` changes stored text only for pipelines that fetch HTML with `url_fetcher`: `url.generic`, `url.repo`, `url.github.issue`, `url.github.pr`, `url.github.release`, `url.github.profile`, `url.github.starred`. `url.github.repo` uses the GitHub API fetcher and has no `html_cleaner`. `url.interactive` and `url.authenticated` fetch through `ibr`, which usually returns plain text that passes through unchanged; they are left out of the selector.
- **Selector predicate** — `(pipeline LIKE 'url.generic%' OR pipeline LIKE 'url.repo%' OR pipeline LIKE 'url.github.issue%' OR pipeline LIKE 'url.github.pr%' OR pipeline LIKE 'url.github.release%' OR pipeline LIKE 'url.github.profile%' OR pipeline LIKE 'url.github.starred%')`. (Stored values carry a version suffix such as `url.generic@v0`, hence `LIKE 'name%'`.)
- **Versioned pipeline?** — no. Built-in pipelines carry no version yet; existing objects are selected by pipeline name.
- **Estimated wall-clock** — one re-fetch and pipeline run per stored web page; depends on corpus size and the sites' response times.
- **Estimated LLM cost** — these pipelines run tagging, entity extraction and embedding steps, so cost scales with the number of re-ingested pages and the configured providers. `ctxt upgrade run --budget` does not bound it: re-ingest reports a cost of 0, so the budget is never reached.

#### Known limits of the upgrade run

- **A dead link stops the run.** Re-ingest fetches each page again. The first object whose page now fails (404, timeout, blocked) ends the whole run, and the next run starts again from the oldest object, so it stops at the same one. Until the worker skips permanent failures, narrow the selector so the run avoids the failing page: add `AND created_at > '<timestamp of the failing object>'` to continue past it, work through `created_at` ranges, or exclude a source with `AND source NOT LIKE 'https://host.example/%'`. `ctxt upgrade status` shows the failing object.
- **Titles.** Re-ingest builds its draft without the object's metadata, so a title set from a feed item or by the user is replaced by the page's HTML `<title>`.
- **Duplicates on recapture.** The content hash of an object is not recomputed on re-ingest: it still describes the raw HTML stored at first capture. New captures hash the cleaned text, so capturing a URL again after this release creates a second object instead of reinforcing the existing one, whether or not the old object was re-ingested. Delete or merge the older object if that matters to you.

## Upgrade walkthrough

1. **Before upgrading** — back up: `dpkms backup` (add `--include-blobs` to keep local blobs).
2. **Pull / install** — install the release as usual.
3. **Preview** — `ctxt upgrade run --filter "where:(pipeline LIKE 'url.generic%' OR pipeline LIKE 'url.repo%' OR pipeline LIKE 'url.github.issue%' OR pipeline LIKE 'url.github.pr%' OR pipeline LIKE 'url.github.release%' OR pipeline LIKE 'url.github.profile%' OR pipeline LIKE 'url.github.starred%')" --dry-run` lists the pages to re-ingest.
4. **Run** — `ctxt upgrade run --filter "where:(pipeline LIKE 'url.generic%' OR pipeline LIKE 'url.repo%' OR pipeline LIKE 'url.github.issue%' OR pipeline LIKE 'url.github.pr%' OR pipeline LIKE 'url.github.release%' OR pipeline LIKE 'url.github.profile%' OR pipeline LIKE 'url.github.starred%')"`. Re-ingesting fetches each page again: content that changed upstream changes, and a page that disappeared stops the run (see the known limits above).
5. **Verify** — `ctxt upgrade status --watch` until done.
6. **Roll back if needed** — `dpkms restore <archive>`.
