## Changes by bucket

### `none` changes (no operator impact)

#### `feat(config): adopt kit/core/config + kit -c/--config global` — T-0199

- **What changed**:
  - `internal/config.Load` now layers files via `hop.top/kit/go/core/config.Load` (system → user → project → CLI extras → CLI overrides) instead of the previous hand-rolled `viper.MergeInConfig` cascade. Defaults and env-binding still go through viper; only the file-merge stage moved to the kit primitive.
  - New `internal/config.LoadWithOverrides(bin, cfgFile, paths, overrides)` exposes the layered + CLI-override entry point used by both bins.
  - `cmd/ctxt` and `cmd/dpkms` both **drop their local `--config` flag** in favor of kit/cli's `-c/--config` global (registered as `StringArrayP`, repeatable, supports bare paths and `key=value` overrides). Without this drop, ctxt/dpkms panicked at init with "flag redefined: config".
  - `internal/cursor/cursor.go`, `internal/repl/history.go`, and `internal/ambient/buffer/local/local.go` migrate from raw `os.Getenv("XDG_*_HOME")` to `hop.top/kit/go/core/xdg` (`RawConfigDir`, `RawDataDir`, `RawStateDir`).
  - All `mapstructure`-tagged `Config` fields (61 of them) now also carry mirroring `yaml` tags so kit's `yaml.v3`-based file decode produces the same struct shape as viper's `mapstructure` decode.
- **Why now**: T-0199 audit flagged `kit/core/config.Load` non-adoption, direct XDG env reads, and the `--config` global collision as P0 once kit's `-c/--config` global landed.
- **Behavior delta for users**:
  - `--config <path>` (single string) → use `-c <path>` (kit's bare-path mode does the same thing).
  - New: `-c key=value` and `-c <path>` can be combined and repeated. Bare paths layer after the discovered cascade; `key=value` overrides win over every file layer.
  - macOS REPL history file: now respects kit/xdg's macOS-aware `RawDataDir`, so `~/Library/Application Support/contexthelp/repl_history` instead of the prior hard-coded `~/.local/share/contexthelp/repl_history`. No data migration needed; the file is regenerated on use. (`dataDirXDG` already used kit/xdg, so this aligns REPL history with the rest of the data-dir resolution.)

## Upgrade walkthrough

No upgrade steps. `make install` (or equivalent) and the new bins drop in with identical semantics for unflagged invocations. CLI users of the old `--config <path>` should switch to `-c <path>`.
