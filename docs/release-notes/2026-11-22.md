## Highlights

### Opt-in pod-backed daemon runner (`daemon.runner: pod`)

- **Ambient daemon (`ctxt capture --ambient`)** and **server lifecycle (`dpkms serve`, `dpkms ps`, `dpkms shutdown`)** can now adopt an existing pod via the standalone `pod` CLI by setting `daemon.runner: pod` in user config or passing `--runner pod --pod <name>`.
- **Local default unchanged:** When `daemon.runner` is `local` (default), `pod` is never searched on `PATH` and no pod code executes. When `runner=pod` is requested without `pod` installed, commands exit with code `70` (`PREREQUISITE`) and never silently fall back to local execution.
- **Security & isolation:** Project-layer config files (`.contexthelp/ctxt.yaml`, `.contexthelp/dpkms.yaml`) are refused if they set `daemon.*`. Remote `dpkms serve` launches always enforce `--runner local` and include `127.0.0.1` in `server.allowed_hosts` for loopback forwarding.
- See [`docs/pod-runner.md`](../pod-runner.md) for setup, lifecycle, and cost guardrails.
