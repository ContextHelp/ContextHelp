# Messaging (context.help)

This document defines site messaging inspired by creator-first platforms, but adapted to **context publishing**.

## Positioning

context.help is the home for publishing and subscribing to **curated context**.

It pairs an open, self-hostable **node** (sovereign by default) with an optional **cloud** offering for teams that don't want to run infrastructure.

- Publishers ship **registries** (structured, versioned context feeds)
- Subscribers pull **index-level context** by default, and fetch details **just-in-time**
- Every output can carry **traceability** (receipts + provenance)

## Core promises (homepage bullets)

- **Built for pull**: subscribers fetch what they need, when they need it
- **Thin sync + JIT detail**: distribution without bulk copying by default
- **Traceable by design**: receipts and provenance make outcomes auditable
- **Sovereign by default**: nodes are local-first and self-hostable; no forced vendor lock-in
- **Polyglot + multimodal**: publish and consume context across languages and formats
- **Decentralized distribution**: registries can live anywhere; the protocol stays open
- **Works for teams**: access controls, quotas, and enterprise-ready admin in context.help cloud
- **Open core**: policy enforcement stays OSS; cloud adds admin, billing, marketplace

## Publisher page copy blocks

### What you publish

- A registry is a curated set of entities, taxonomies, edges, and safe summaries.
- Subscribers can sync the index and pull full detail just-in-time.

### How you monetize

- Paid subscriptions to your registry
- Credits for metered operations (JIT pulls, exports, derivations)
- Paid extensions (plugins/pipelines/templates)

### How you protect value

- Index-first distribution by default (no bulk replication)
- Quotas and metering discourage scraping
- Receipts provide traceability without DRM

### How you stay sovereign

- Your registry can be hosted anywhere (including self-hosted)
- Subscribers use nodes that enforce policy locally
- Export/import remains portable by design

## Buyer page copy blocks

### Why context beats newsletters

- Searchable and queryable
- Integrated into workflows (profiles, pipelines, agents)
- Always current (updates are incremental)
- Bounded and controllable (policy, quotas)

## Terminology (site)

- **Registry**: a published context feed (structured, versioned)
- **Node**: where subscribers use and enforce policy (self-hosted or cloud-managed)
- **Thin sync**: index/schema replication without full bodies
- **JIT pull**: fetch full content only when needed
- **Receipt**: signed record of what was delivered and why

## Principles to reinforce (site)

- **Sovereign**: users and teams own their nodes and data
- **Federated**: knowledge can live anywhere; subscription is not central dependency
- **Polyglot**: multilingual by design
- **Verifiable**: provenance and receipts travel with outputs

## Tone

- Creator-respecting, not hypey
- Concrete, operational language
- Emphasize trust, provenance, and "living" value
